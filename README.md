# NutriTrack

Persönliches Ernährungs- und Trink-Tagebuch als **einzelne HTML-Datei** (`index.html`).
Deutsche Oberfläche, läuft komplett im Browser, Daten liegen lokal und lassen sich optional mit Supabase synchronisieren.

Live: https://darkweezer.github.io/dwNutriTrack/

## Funktionen

- Datumsnavigation durch die Tage
- Karten für Flüssigkeit, Mahlzeiten und Energie, jeweils mit Zielwerten
- Schnellerfassung für Trinken und Essen über Kacheln (bearbeitbar, Uhrzeit-Dialog, automatische Kategorie)
- Essens- und Trinkprotokoll pro Tag mit Bearbeiten und Löschen
- Zwei Wochenverläufe: Trinken (Kaffee als zweite Säule) und Kalorien
- JSON-Export und -Import (zusammenführen oder ersetzen)
- Synchronisation mit Supabase inklusive Anmeldung (☁️), auch für die Schnellauswahl

## Technik

Tailwind CSS, Chart.js 4.4.1 und supabase-js 2, alles per CDN. Es gibt keinen Build-Schritt und keinen Server.

## Benutzung

1. `index.html` im Browser öffnen oder die Live-Seite aufrufen.
2. Ohne Supabase werden alle Daten im `localStorage` des Browsers gespeichert. Sie gelten nur für dieses Gerät und diesen Browser. Ein regelmäßiger JSON-Export dient als Sicherung.

## Supabase einrichten (optional)

Mit Supabase lassen sich die Daten geräteübergreifend abgleichen. Der Zugriff ist nur nach Anmeldung möglich.

### 1. Projekt anlegen

Auf https://supabase.com ein kostenloses Projekt erstellen.

### 2. Tabellen anlegen

Im **SQL Editor** ausführen:

```sql
-- Mahlzeiten
create table food_logs (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  meal_type text,
  description text,
  calories int,
  notes text
);

-- Getränke
create table water_logs (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  amount_ml int,
  type text,
  icon text
);

-- Einstellungen, derzeit die Schnellauswahl-Kacheln
create table app_settings (
  key text primary key,
  value jsonb not null,
  updated_at timestamptz default now()
);
```

Die App erkennt fehlende Spalten (`calories`, `notes`, `icon`) selbst und läuft dann mit weniger Daten weiter. `app_settings` ist nur nötig, wenn die Schnellauswahl synchronisiert werden soll.

### 3. Zugriffsschutz (RLS)

Row Level Security muss aktiv sein, damit nur angemeldete Nutzer Daten lesen und schreiben können:

```sql
alter table food_logs    enable row level security;
alter table water_logs   enable row level security;
alter table app_settings enable row level security;

create policy "nur angemeldet" on food_logs
  for all to authenticated using (true) with check (true);
create policy "nur angemeldet" on water_logs
  for all to authenticated using (true) with check (true);
create policy "nur angemeldet" on app_settings
  for all to authenticated using (true) with check (true);
```

> Diese Policy gibt **jedem angemeldeten Nutzer** Zugriff auf **alle** Zeilen. Sie ist für ein Ein-Personen-Tagebuch gedacht. Deshalb unter **Authentication → Providers → Email** die Selbstregistrierung ausschalten („Allow new users to sign up“) und den eigenen Nutzer manuell anlegen.

### 4. Nutzer anlegen

Unter **Authentication → Users → Add user** einen Nutzer mit E-Mail und Passwort erstellen.

### 5. Zugangsdaten in der App eintragen

1. In Supabase unter **Project Settings → API** die **Project URL** und den **anon/publishable key** kopieren.
2. In der App auf ☁️ klicken, URL und Key eintragen, mit E-Mail und Passwort anmelden.

URL und Key werden nur im `localStorage` deines Browsers gespeichert, nicht im Code. Das Passwort wird nicht gespeichert, nur die Anmeldesitzung.

**Wichtig:** Niemals den `service_role`- oder `secret`-Key verwenden oder committen. Der anon/publishable key ist für den Browser gedacht und ist durch RLS abgesichert.

### So funktioniert der Abgleich

- Zuerst werden lokale Änderungen hochgeladen: Löschungen, neue und geänderte Einträge.
- Danach wird vom Server geladen. Der Server gewinnt, außer bei lokal noch nicht hochgeladenen Änderungen.
- Datum und Uhrzeit eines Eintrags werden in `created_at` gespeichert.
- Ohne Verbindung bleibt alles lokal und wird beim nächsten Abgleich nachgeholt.

## Datenmodell (localStorage)

| Schlüssel | Inhalt |
|---|---|
| `nutritrack_data_v1` | Einträge pro Tag: `{ "YYYY-MM-DD": { meals: [...], fluids: [...] } }` |
| `nutritrack_fluid_goal`, `nutritrack_kcal_goal` | Tagesziele |
| `nutritrack_quick_drinks`, `nutritrack_quick_food` | Schnellauswahl-Kacheln |
| `nutritrack_supabase` | Supabase-URL und Key (nur im Browser) |
| `nutritrack_sb_auth` | Anmeldesitzung |
